4. Users & roles (multi-user)

Two layers must stay aligned. No UI change — same login form and Admin screens.

4.1 Layer A — UI access (js/auth.js)

  • Defaults: ROLE_CONFIG (pages, admin tabs, canEditAllTickets, …).
  • Overrides: Admin → Roles → Save writes config.rolePermissions in Supabase (localStorage cache in IndexedDB dev mode only).
  • Session: sessionStorage.pulse_session with { name, role } after login.
  • Login (Supabase mode): email + password form → supabaseSignIn → load profiles row. No Name dropdown.
  • Checks: canAccessPage(), applyRoleAccess(), canEditTicket().

4.2 Layer B — database access (Supabase RLS)

  • Identity: Supabase Auth JWT → auth.uid().
  • Role: profiles.role (enum: admin, supervisor, operator, account_manager, …).
  • Policies: current_user_role() in 002_rls_policies.sql and follow-on migrations.
Critical rule: Admin Personnel sets auth email/password via RPC. Postgres profiles.role controls what data RLS allows. Adding a user requires: Auth account + profiles row with correct role and display_name.

7. Realtime push — replace Supabase polling

7.1 Principle (implemented June 2026)

  • Do not poll getAllOrders / getAllOrdersSummary on a timer for multi-user sync.
  • Do subscribe via Supabase Realtime (postgres_changes) per table in js/supabase-client.js.
  • On event: fetch affected row(s) and patch in-memory list / re-render queue; dispatch pulse:order-change, pulse:reference-data-changed, pulse:task-change.
  • Pages register refresh via onDBUpdate() in js/shared.js.
  • No fallback poll if WebSocket disconnects (known limit — user may need manual refresh).
  • UI timers only: operator clock 1s, job-ticket step banner 30s — not Supabase polls.

7.7 Cost / load control (why this won’t “blow up” Supabase)

  • Realtime messages are small (change metadata); heavy work is avoided by not refetching all orders per event.
  • Client already sets realtime: { params: { eventsPerSecond: 10 } }.
  • Debounce: multiple workflow step updates in 2s → one patch.
  • Skip processing when document.hidden.
  • Do not subscribe on pages that don’t need live data (e.g. pricing-calculator).
