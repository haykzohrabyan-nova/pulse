3. Payment strategies (business rules)

Strategy Payment required to start production After production starts Price confirmation
Partial Deposit only Client can pay remaining balance (checklist shows “Collect remaining balance”). Status: Active · balance due if balance > 0. Required unless depHandling === 'cash' (then auto-unchecked in Payment UI; not required on quote).
Pay in full 100% of quote total No remaining balance UI; summary says “Paid in full — no remaining balance.” Required unless cash-only full pay (see edge cases).
$0 upfront / Net None Payment step marked done; follow-up date tied to net terms (10–60 days). If requireClientConfirm: production after client confirms only. Else production can start immediately.

Key computed fields (computeCheckout return)

  • dueNow — Full: quote total. Partial: deposit amount. Net: 0.
  • balance — Partial only: quote total − deposit due (not necessarily remaining if overpaid).
  • paid — getPaidAmount() capped at quote total.
  • remaining — quote total − paid.
  • paymentOk — Production payment gate met (partial = deposit satisfied; full = fully paid; net = always true).
  • depositPaid — Partial strategy && deposit satisfied.
  • fullyPaid — remaining ≤ $0.01.
  • canCollectPayment — User can open pay modal (partial/full with remaining > 0).
  • canReleaseProduction — All gates pass; quote may auto-set productionReleasedAt.

4. Production gates & status labels

canReleaseProduction =
  NET:     (!needConfirm) OR (confirmed)
  PARTIAL: priceStepDone AND depositPaid
  FULL:    cashInPerson ? fullyPaid : (priceStepDone AND fullyPaid)

priceStepDone =
  !needConfirm OR priceConfirmed OR shouldAutoConfirmOnFullPayment()

needConfirm =
  !cashInPerson AND !partialCashDeposit AND requireClientConfirm !== false

Checklist steps (crm-quote)

  1. Quote price confirmed — Hidden when cash-in-person full or partial cash deposit. Action: confirm-price.
  2. Deposit / payment — Done when: net (always), partial (deposit paid + price ok), full (fully paid + price ok).
  3. Ready for production — Done when productionReleasedAt is set. Auto-set by maybeAutoStartProduction() when canReleaseProduction becomes true.

Status badge labels

ConditionLabel
productionReleasedAt + partial + remaining > 0Active · balance due
productionReleasedAtActive · in production
Blocked, need confirmAwaiting confirmation
Blocked, need paymentAwaiting payment
Gates pass, not startedReady for production

5. Payment settings UI (payment.html)

Strategy panels

  • settingPanelPartial — Deposit %/$, deposit collection (cash vs gateway), balance channels (always visible).
  • settingPanelFull — Full payment channel checkboxes; cash is exclusive (selecting cash unchecks others).
  • settingPanelNet — Payment due period 10–60 days; drives read-only reminder start date.

Deposit collection (partial) — UI side effects

depHandlingRequire client confirmationFollow-up (partial cash)
cashUnchecked automaticallyFollow-up schedule stays visible & enabled
gatewayChecked automaticallyNormal follow-up rules

Function: syncQuoteDeliveryOptionsUi() in payment.html.

Pay in full — cash channel

  • Checking Cash unchecks all other channels (onFullChannelChange).
  • Checking any other channel unchecks Cash.
  • When cash-only: client confirmation off, follow-up master off, follow-up card hidden.
  • When cash not selected: confirmation on, follow-up on.

Remote quote & follow-up sections

  • remoteQuoteCard — Send quote via SMS/email, destination fields, client confirmation checkbox (may move to fullConfirmAnchor for full strategy).
  • followUpScheduleCard — Separate card; always shown for partial cash (not hidden with remote quote).

Save behavior

savePaymentConfig() → validates → PQP.savePaymentConfig(cfg). If full cash + receipt ID on file, applyFullCashCheckoutState(token) pre-fills quote payment as paid in full.

6. Quote UI (crm-quote.html)

Render pipeline (renderQuote)

  1. paymentCfg = PQP.loadPaymentConfig()
  2. quoteState = PQP.loadQuoteState(token)
  3. checkout = PQP.computeCheckout(paymentCfg, ticket, quoteState)
  4. ensureFullCashQuoteConfirmed() if cash-in-person paid
  5. maybeAutoStartProduction() if canReleaseProduction
  6. renderCheckout() — stepper, summary, blocked banner

Record payment modal

Methods: cash, zelle, wire, ach, check, card. Method-specific steps in renderPayMethodPanel(method):

  • Wire / ACH — Bank details from PAYMENT_REMITTANCE with copy icons per field; screenshot upload step 2.
  • Zelle — Zelle address + quote reference with copy button.
  • Card — Card fields + photo ID upload.
  • Cash — Receipt ID.
  • Check — Instructions + screenshot.

Pay modal modes (openPayModal)

ModeWhenAmount shown
depositPartial, nothing paid yetDeposit due
balancePartial, deposit paid, remaining > 0Remaining balance
fullFull strategy or cash-in-personQuote total

On payment save (payModalSave)

  • Accumulates payment.totalPaid, sets depositRecordedAt / balanceRecordedAt / fullRecordedAt as appropriate.
  • Full pay may auto-set quotePriceConfirmed + clientConfirmed.
  • If afterCheckout.canReleaseProduction, sets productionReleasedAt automatically.

8. End-to-end flows

Flow A — Partial: deposit then production, balance later

  1. Admin sets strategy partial, deposit 30%, gateway or cash, saves config.
  2. On quote, client confirms price (if required).
  3. Staff records deposit via modal → depositRecordedAt, totalPaid updated.
  4. computeCheckout → canReleaseProduction true → maybeAutoStartProduction sets productionReleasedAt.
  5. Status Active · balance due; user can still Collect remaining balance.

Flow B — Full: pay 100% then production

  1. Admin sets strategy full, selects channels (not cash-only unless in-person).
  2. Client confirms price if required; pays full amount in modal.
  3. When fullyPaid, production auto-starts; no further pay buttons.

Flow C — Net: no upfront payment

  1. Admin sets strategy net, due period (e.g. 30 days), follow-up date syncs.
  2. If confirmation required: confirm price → production starts.
  3. If confirmation not required: production can start immediately on load.

Flow D — Admin pre-records cash (config receipt ID)

  1. Partial cash: save Payment with receipt ID → getPaidAmount treats deposit as paid from config (no modal needed for deposit gate).
  2. Full cash-only: applyFullCashCheckoutState marks quote paid + confirmed.

9. Cash, confirmation & follow-up edge cases

ScenarioBehavior
Partial + cash deposit partialCashDeposit true; price step hidden; confirmation not required; balance channels always visible; follow-up schedule visible.
Full + cash only cashInPerson true; all channels forced off except cash; confirmation off; follow-up off; receipt ID required in Payment settings.
Full + cash + other channels Not allowed in UI — cash selection is exclusive.
Config receipt without modal hasConfigDepositReceipt / hasConfigFullCashReceipt bump getPaidAmount for preview quote token.
Quote token resolution URL ?id= or ?q=, else previewQuoteToken from config, else DEFAULT_QUOTE_TOKEN.
