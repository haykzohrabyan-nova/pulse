Pulse → Supabase Migration

Import Admin Export JSON into this browser, then push all admin + production data to Supabase (personnel, machines, dies, organisation, products, workflows, roles, orders, and more). Same URL: …

Before you start

IndexedDB is per browser + per URL. If Dashboard shows orders on another URL (e.g. file://), export JSON there first, then import here.
Anon key must start with eyJ (Settings → API → anon public). Use project Auth email/password, not your supabase.com login.

Step 1 — Supabase connection

Required for RLS on insert. Seeded users: admin@bazaarprinting.com / Pulse2026!

Step 1b — Preflight check (run before migrating)

Verifies Supabase tables exist, you are signed in with a role that can write, and compares browser IndexedDB vs cloud row counts. Runs a harmless config write test (insert + delete).

    Step 2 — Import backup (this browser)

    Data lives at … only. Export from the browser that has your real Pulse data.

    Admin → Export JSON includes: Personnel, Machines, Dies, Organisation, Products, Workflows, Roles, plus orders, activity, invoices, etc.

    Step 3 — Push everything to Supabase

    Migrates: config (catalog, roles, machine capacity, personnel), machines, product workflows, organisation, dies, knowledge base, operator sessions/points, invoices, orders, activity log. Devices/reprints stored in config (no Postgres table).

    Step 4 — Switch Pulse to Supabase

    Edit pulse-config.local.js: real URL + anon key, then
    window.PULSE_STORAGE_BACKEND = 'supabase';
    Hard-refresh Dashboard — console: Storage backend: Supabase.
